# Known limits

Things we have run into and have **not solved** (or only reduced). Fix them later if time allows. Solved problems are not listed here; they are in the reports. Last updated 2026-11-07 (new section: planned work after the Q4-Q6 runs), first written 2026-11-05 from reports 01-14, the Stage 3 validation report, the Stage 4 handoff, `.omo/PROJECT_ARCHITECTURE.md` and the notes of runs 1-5 of the Mamba question.

"Where" points to the document with the evidence. "Effect" is what it costs us today. Items marked *(not re-checked)* come from an older report and I did not verify that they still hold.

| # | Limit | Effect | Status / idea | Where |
|---|---|---|---|---|

| 3.3 | The judge prompt and its model live **on the host**, not in this repo. ## Planned work after the Q4-Q6 runs: Loop 2 and the Stage 3 fixes

Decision (2026-11-07): run the remaining test questions (Q4 to Q6) first, then build Loop 2 and fix Stage 3. Reason: Q1 to Q3 already show that the biggest losses are not in retrieval, and three more topics give the statistics needed to choose the rules. Working rules for everything below, from what went wrong before (judge V2.1, the aspect splitter prompt, the topic aspect):
- Write the pass rule BEFORE the experiment; test on stored data first, then in one real run.
- **One change per run**, with `PLAN_CACHE=true` so the sub-questions are identical; the topic aspect was blamed on a run that changed five things at once.
- An effect has to be tested where it happens (the topic aspect looked good on stored digests and failed in the digest prompt).
- No change to a judge prompt or a threshold without before/after numbers on held-out labeled rows. All labels so far are LLM labels.

### A. Loop 2: search again for aspects the evidence does not cover
Query step exists (`gap_queries.py`, report 14), nothing else does. Design: `docs/reports/TRACE Stage 3 Coverage Validation Report.md` section 11.

## How to use this file
